Here are the commands for managing the hardware bitstream on the Kria KV260, followed by the specific solutions to the errors you encountered during the hardware-to-ROS 2 integration.

### 1. Kria KV260 Bitstream Commands (`xmutil`)

Xilinx uses the `xmutil` tool to hot-swap FPGA hardware designs (apps) on the Kria board without needing to reboot Linux.

* **List all installed bitstreams:**
```bash

sudo xmutil listapps



```


* **Unload the active bitstream:**
*(Crucial step: You must always unload the current app before loading a new one, otherwise the load command will silently fail).*
```bash

sudo xmutil unloadapp



```


* **Load your custom bitstream:**
*(Replace `<your\_app\_name>` with the name of your firmware directory located in `/lib/firmware/xilinx/`).*
```bash

sudo xmutil loadapp <your\_app\_name>



```



### 2. Solutions to Errors Encountered

**Problem: Changing Memory Address Crashes**
Every time the Kria reboots or a new bitstream is loaded, Linux assigns a new physical address to your direct memory access (`udmabuf0`). If your C++ code uses an old address, the node will crash.

* **Solution:** Always query the active physical address before running your node.
```bash

### To initialize U-DMA buffer
sudo insmod udmabuf/u-dma-buf.ko udmabuf0=4194304
###To remove U-DMA buffer
sudo rmmod udmabuf/u-dma-buf.ko

cat /sys/class/u-dma-buf/udmabuf0/phys\_addr



```


*Take the hex output from this command and update the `phys\_in` variable in your C++ code.*

**Problem: "Bus Error" when Generating Images**
OpenCV uses high-speed ARM NEON vector instructions to process images. The ARM architecture strictly prohibits running these instructions on uncached device memory (memory mapped with the `O\_SYNC` flag), resulting in an immediate Bus Error.

* **Solution:** Map the image buffer as cached, while keeping the AXI hardware registers uncached.
1. Open `/dev/udmabuf0` (Image Data) **without** `O\_SYNC`.
2. Open `/dev/mem` (AXI Registers) **with** `O\_SYNC`.
3. Manually flush the cache to DDR RAM before the FPGA reads it, and invalidate it before the CPU reads the result back:
```cpp

// Flush CPU cache before FPGA trigger

int sync\_dev = open("/sys/class/u-dma-buf/udmabuf0/sync\_for\_device", O\_WRONLY);

if(sync\_dev >= 0) { if(write(sync\_dev, "1", 1) < 0) {} close(sync\_dev); }



// (Trigger AXI Registers Here)



// Invalidate CPU cache so OpenCV sees the new FPGA data

int sync\_cpu = open("/sys/class/u-dma-buf/udmabuf0/sync\_for\_cpu", O\_WRONLY);

if(sync\_cpu >= 0) { if(write(sync\_cpu, "1", 1) < 0) {} close(sync\_cpu); }



```





**Problem: `Package 'ov\_msckf' not found\*\*`
ROS 2 could not find the OpenVINS packages because the terminal was only searching the default `/opt/ros/humble` directories instead of your custom workspace.

* **Solution:** You must source the local install setup file from the root of your workspace in every new terminal window before launching.
```bash

cd \~/openvins\_ws

source install/setup.bash



```
